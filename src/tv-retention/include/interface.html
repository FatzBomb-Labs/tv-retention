About

    

      
TV Retention 

      
Keeps a chosen number of days, episodes, or seasons per series and removes the rest through Sonarr, so Sonarr's database and monitoring stay correct.

      
The plugin touches no filesystem of its own. Sizes, air dates, import dates and monitoring all arrive with the episodes, and deletion is a Sonarr call — so Sonarr's recycle bin, its extra-file handling and its empty-folder cleanup all apply as they are.

      

    

  


  


    
Help

    
How a rule decides

    
A rule may set any combination of keep days, keep episodes, and keep seasons. Each condition votes on every episode, and the combine mode settles disagreements.

    

      
Combine modeAn episode is deleted whenEffect

      
        
Earliestevery condition says soKeeps the most. The safe default.

        
Latestevery condition says so, and none was undecidableKeeps the least, without acting on an unknown.

        
Anyany condition says soMost aggressive. Ignores conditions it cannot judge.

      
    

    
What is never deleted

    
    
      
  • Anything belonging to a series that is blocked by an error.
    • 
      
  • Media files Sonarr does not know about — they are reported instead.
    • 
      
  • Specials, unless you include them.
    • 
      
  • Episodes that have not aired yet, whatever the rule says about the old ones.
    • 
      
  • Everything, on a scheduled run while Test Mode is on.
    • 
    

    
Monitoring

    
Unmonitor only never asks Sonarr to fetch anything: it unmonitors what it deletes, and whatever falls outside the keep window. Full sync also monitors everything inside the window, including episodes with no file — which asks Sonarr to download them. Deleting a file always unmonitors it in both modes; anything else would have Sonarr fetch it back and the next run delete it again.

    
Where the data comes from

    
Sonarr is read once a day, and everything on screen is answered from that reading — which is why nothing here waits on it. The age is shown beside the scheduled changes, the refresh control at the top syncs on demand, and a run always reads Sonarr again before it acts.

    
Air dates

    
Sonarr's air date is used first, then TMDB if a key is set, then an estimate from the episodes either side, then the date Sonarr first acquired the episode. The source of each date is shown against every episode, so it is clear when a decision rests on an estimate rather than a real air date.

  


  
  

    
Alert settings

    
An alert is a fact about the present: it appears when its condition becomes true and clears itself when the condition clears. Nothing here changes what is true — only how loudly you are told about it.

    

      

        Count in the header
        
      

      Badges beside each section always show, whatever this says. An error blocks a series from running, so it is always counted.
      
      Acknowledging hides one until it changes. If what it says changes — a different error from Sonarr, a different count — it comes back, because it is no longer the same fact. Errors can never be acknowledged.

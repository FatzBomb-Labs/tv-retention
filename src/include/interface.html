About

    

      
TV Retention

      
Keeps a chosen number of days, episodes, or seasons per series and removes the rest through Sonarr, so Sonarr's database and monitoring stay correct.

      
TV Retention touches no media filesystem. Sizes, air dates, import dates and monitoring all arrive with the episodes, and deletion is a Sonarr call — so Sonarr's recycle bin, its extra-file handling and its empty-folder cleanup all apply as they are.

      

    

  


  


    
Adding a series

    
There is no separate "add" screen. A series Sonarr holds and a series you already manage are the same row in the same list, so you find the show under Series and click it. The editor opens beside the list.

    
    
      
  1. Open Series → Not watching and search for the show.
    2. 
      
  2. Set how much to keep: a preset, or Custom values for this show alone. Custom is the default.
    3. 
      
  3. Press Save and enable, or Save to add it switched off until you are ready.
    4. 
    

    
Nothing is deleted by saving. The next-run lines in the editor say what the first run would do, and they move as you type, so you can see the consequence of a keep value before you commit to it.

    
What is never deleted

      
    
        
  • Anything belonging to a series that is blocked by an error.
    • 
        
  • Media files Sonarr does not know about — they are reported instead.
    • 
        
  • Specials, unless you include them.
    • 
        
  • Episodes that have not aired yet, whatever the rule says about the old ones.
    • 
        
  • Everything, on a scheduled run while Test Mode is on.
    • 
      

  


  



    
Connecting apps

    
Sonarr is the only connection this needs. Add it under Settings → Connections with its URL and API key, and press Test & save: it reports the version, counts the series, and says whether Sonarr has a recycle bin configured.

    
If Sonarr has no recycle bin, everything it deletes is permanent — including what is asked for here. That raises a warning with a one-click fix.

    
More than one Sonarr is supported, and each series belongs to exactly one of them. An instance can be disabled without deleting it, which leaves its rules in place and stops them being processed.

      
Everything on screen is answered from the stored reading, so the page never waits on Sonarr. The worker refreshes it regularly, opening or returning to the page starts a quiet refresh when appropriate, and the age remains visible beside scheduled changes. A run always reads Sonarr again before it acts.

  


  



    
Managing presets

    
A preset is a named set of keep values shared by any number of shows — Keep 30 days, Keep 2 seasons. Raise the preset and every show pointing at it widens at once, with no show-by-show editing.

    
A preset is the single source of truth for the shows using it, so those shows store no numbers of their own: a card using a preset shows one blue pill, and only a custom rule spells its values out. A preset still in use cannot be deleted.

    
Use Custom when a show's retention is genuinely its own. A new series starts on Custom, so it never picks up a preset's values without you choosing them.

  


  



    
Monitoring

      
A run only ever unmonitors. It unmonitors what it deletes, and whatever falls outside the keep window — including episodes with no file, which are never deleted, so nothing else would reach them and Sonarr would go on fetching what the next run removes.

    
Deleting a file always unmonitors it. Anything else would have Sonarr fetch it back and the next run delete it again, for ever. That is why no setting can switch it off.

    
Nothing here ever monitors on a schedule. Monitoring an episode with no file asks Sonarr to download it, which can be hundreds of episodes. It happens once, and only when you ask: save a series whose keep window has grown, and the editor offers to monitor the episodes that growth brought in.

    
To keep an episode outside the keep window, exclude it first. An excluded episode is set aside before the keep window is worked out, so it is in neither half of it and nothing here ever touches its monitored flag — whatever you set in Sonarr afterwards stays set. Without the exclusion, the next run unmonitors it. The exclusion picker offers the monitored flag beside each episode, so the whole decision is made in one place.

  


  



    
Rules & meanings

    
How a rule decides

      
A rule may set any combination of keep days, keep episodes, and keep seasons. Each condition votes on every episode, and the combine mode settles disagreements.

      

        
Combine modeAn episode is deleted whenEffect

        
          
Earliestevery condition says soKeeps the most. The safe default.

          
Latestevery condition says so, and none was undecidableKeeps the least, without acting on an unknown.

          
Anyany condition says soMost aggressive. Ignores conditions it cannot judge.

        
      

      
Sonarr's air date is used first, then TMDB if a key is set, then an estimate from the episodes either side, then the date Sonarr first acquired the episode. The source of each date is shown against every episode, so it is clear when a decision rests on an estimate rather than a real air date.

  


  



    
Scheduling

    
Set when runs happen under Settings → Schedule. The worker keeps its own time: it decides what is due, sleeps, and decides again, so a run missed while the container was stopped is caught up rather than skipped, and one held back because Sonarr was unreachable goes as soon as it answers. Exactly one is ever queued.

    
Test Mode is on for a new install and means nothing writes — scheduled or manual, no exceptions. A run does everything except write and marks its output [TEST MODE]. The Run button says which of the two it is about to do: orange reports, blue deletes.

    
Set TZ in your compose file, or "daily at 4am" will mean 4am somewhere else.

Air date resolution

    
A rule that keeps by age needs a date for every episode it judges. Sonarr supplies one for almost everything with a broadcast slot, so this is rare — but when a series has no dates, a keep-by-age rule quietly finds nothing to act on.

    

      
If Sonarr has no air date, ask these in order
        

        The first enabled service that answers wins, so the order is the setting. A service you cannot use yet is listed with the reason why. TVDB is not listed: it is Sonarr's own metadata source, so if Sonarr has no date then TVDB has none either.

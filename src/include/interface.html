About

    

      
TV Retention

      
Keeps a chosen number of days, episodes, or seasons per series and removes the rest through Sonarr, so Sonarr's database and monitoring stay correct.

      
The plugin touches no filesystem of its own. Sizes, air dates, import dates and monitoring all arrive with the episodes, and deletion is a Sonarr call — so Sonarr's recycle bin, its extra-file handling and its empty-folder cleanup all apply as they are.

      

    

  


  


    
Adding a series

    
There is no separate "add" screen. A series Sonarr holds and a series you already manage are the same row in the same list, so you find the show under Series and click it. The editor opens beside the list.

    
    
      
  1. Open Series → Not watching and search for the show.
    2. 
      
  2. Set how much to keep: a preset, or Custom values for this show alone. Custom is the default, because sharing values with other shows is a decision rather than a starting point.
    3. 
      
  3. Press Save and enable, or Save to add it switched off until you are ready.
    4. 
    

    
Nothing is deleted by saving. The next-run lines in the editor say what the first run would do, and they move as you type, so you can see the consequence of a keep value before you commit to it.

    
What is never deleted

      
    
        
  • Anything belonging to a series that is blocked by an error.
    • 
        
  • Media files Sonarr does not know about — they are reported instead.
    • 
        
  • Specials, unless you include them.
    • 
        
  • Episodes that have not aired yet, whatever the rule says about the old ones.
    • 
        
  • Everything, on a scheduled run while Test Mode is on.
    • 
      

  


  



    
Connecting apps

    
Sonarr is the only connection this needs. Add it under Settings → Connections with its URL and API key, and press Test & save: it reports the version, counts the series, and says whether Sonarr has a recycle bin configured.

    
If Sonarr has no recycle bin, everything it deletes is permanent — including what is asked for here. That raises a warning with a one-click fix, because it applies to everything Sonarr deletes rather than only to this.

    
More than one Sonarr is supported, and each series belongs to exactly one of them. An instance can be disabled without deleting it, which leaves its rules in place and stops them being processed.

      
Sonarr is read once a day, and everything on screen is answered from that reading — which is why nothing here waits on it. The age is shown beside the scheduled changes, the refresh control at the top syncs on demand, and a run always reads Sonarr again before it acts.

  


  



    
Managing presets

    
A preset is a named set of keep values shared by any number of shows — Keep 30 days, Keep 2 seasons. Raise the preset and every show pointing at it widens at once, with no show-by-show editing.

    
A preset is the single source of truth for the shows using it, so those shows store no numbers of their own: a card using a preset shows one blue pill, and only a custom rule spells its values out. A preset still in use cannot be deleted.

    
Use Custom when a show's retention is genuinely its own. Sharing values with other shows is a decision worth making deliberately, which is why a new series starts on Custom rather than on whichever preset happened to be first.

  


  



    
Monitoring

      
Unmonitor only never asks Sonarr to fetch anything: it unmonitors what it deletes, and whatever falls outside the keep window. Full sync also monitors everything inside the window, including episodes with no file — which asks Sonarr to download them. Deleting a file always unmonitors it in both modes; anything else would have Sonarr fetch it back and the next run delete it again.

    
There is deliberately no third mode that leaves Sonarr's flags alone. It would mean Sonarr re-fetching what a run had just removed and the next run deleting it again — and a setting whose interface needs a danger label is a missing invariant rather than a choice.

    
Full sync can be expensive. Monitoring an episode with no file asks Sonarr to download it, so the mode that never starts a download is the default and an upgrade never moves anyone onto the other one.

  


  



    
Rules & meanings

    
How a rule decides

      
A rule may set any combination of keep days, keep episodes, and keep seasons. Each condition votes on every episode, and the combine mode settles disagreements.

      

        
Combine modeAn episode is deleted whenEffect

        
          
Earliestevery condition says soKeeps the most. The safe default.

          
Latestevery condition says so, and none was undecidableKeeps the least, without acting on an unknown.

          
Anyany condition says soMost aggressive. Ignores conditions it cannot judge.

        
      

      
Sonarr's air date is used first, then TMDB if a key is set, then an estimate from the episodes either side, then the date Sonarr first acquired the episode. The source of each date is shown against every episode, so it is clear when a decision rests on an estimate rather than a real air date.

  


  



    
Scheduling

    
Set when runs happen under Media management → Schedule. The worker keeps its own time: it decides what is due, sleeps, and decides again, so a run missed while the container was stopped is caught up rather than skipped, and one held back because Sonarr was unreachable goes as soon as it answers. Exactly one is ever queued.

    
Test Mode is on for a new install and means nothing writes — scheduled or manual, no exceptions. A run does everything except write, marks its output [TEST MODE], and notifies as a real run would. The Run button says which of the two it is about to do: orange reports, blue deletes.

    
Set TZ in your compose file, or "daily at 4am" will mean 4am somewhere else.

  


  
  

    
Alert settings

    
An alert is a fact about the present: it appears when its condition becomes true and clears itself when the condition clears. Nothing here changes what is true — only how loudly you are told about it.

    

      

        Count in the header
        
      

      Badges beside each section always show, whatever this says. An error blocks a series from running, so it is always counted.
      
      Acknowledging hides one until it changes. If what it says changes — a different error from Sonarr, a different count — it comes back, because it is no longer the same fact. Errors can never be acknowledged.

Safety

    
What stands between a rule and a mistake.

    
What already protects you, and cannot be switched off: Test Mode, which is on for a new install and means nothing writes; queued removals, which only a run applies and which stay undoable until it does; a typed confirmation before a series is removed; deleting a file always unmonitoring it, so nothing can build a fetch-and-delete loop; and unaired episodes never being deleted whatever a rule says about the old ones.


    
Air date resolution

    

      A rule that keeps by age needs a date for every episode it judges. Sonarr supplies one for almost everything with a broadcast slot, so this is rare — but where it bites, it bites silently: a series nothing can date is a series a keep-by-age rule processes and finds nothing in.
      
If Sonarr has no air date, ask these in order
        

        The first enabled service that answers wins, so the order is the setting. A service that cannot be reached yet is shown with the reason rather than left off the list. TVDB is absent on purpose: it is Sonarr's own metadata source, so if Sonarr has no date then TVDB has none either.
